## 1. User request

Today we are designing and developing QDVC Dahdoo, a cute Android app that helps the user record a baby or toddler's cute babbles.

Because cute babbling moments come and go very quickly, it is important that the app starts up quickly to get to a screen where there is a very big button to start a new recording, and that the new recording starts quickly. Loading that is not essential to this central workflow can happen in the background in a non-blocking manner. The big button should be huge, something similar to the Shazam button (diameter is ~50-60% of the width of the screen).

Once a recording is made, it is saved right away, do not block the user with confirmations or catalogue data entry. The full set of recordings can be viewed elsewhere in the app, and catalogue data can be retroactively entered. Suggested fields: which child (maybe establish a list of children in the settings, with birthdays), what was the child doing, what does the child appear to be saying. ### What it does
- **Start-up:** the app opens straight onto the record button, which is about 58% of the screen's width. Nothing loads before that first screen. The folder check and the recordings list load in the background.
- **Recording:** tap to start, tap to stop. Audio goes to the phone's own app storage first, so it never waits for the folder or for a folder to be chosen. It's then copied into your folder automatically. Recordings made before a folder is chosen show an "On phone" label until they move.
- **Saving:** there are no questions after stopping. A small "Saved · Add details" card appears that you can ignore.
- **Details later:** for each recording you can pick which child, what they were doing (with one-tap suggestions from your past answers), what they seemed to say, notes and a favourite star. The child's age at the time is worked out from their birthday.
- **Your folder:** settings, children and recordings all live in it as plain files. Each recording is a `.m4a` with a `.json` file of the same name holding its details. File names are the date and time of recording and never change, so a backup mirror never sees renames.
- **No network:** the app has no network permission. The manifest also blocks any library from adding one back, and Android's cloud backup is switched off for the app.

**Extras I added:**
- a "Record now" launcher shortcut that opens the app already recording
- a notification with a Stop button that keeps recording going if the screen locks
- a default child for new recordings
- automatic stop after 10 minutes, adjustable
- keep-screen-on while recording
- play, share and delete
- a filter by child
- picking up existing settings and recordings when you choose a folder that already has Dahdoo files, such as a restored backup

### Questions before I go further
1. **Audio format.** I chose `.m4a` because it plays and shares everywhere. The catch is that if the app is killed mid-recording, that file may not play. A plain `.aac` file survives being cut off, but some players show its length wrongly. Which do you prefer?
2. **One child per recording, or several?** Siblings often babble together. It's cheap to change the file format now and harder later.
3. **Catch the last 10 seconds?** This is the feature I'd most recommend. While the record screen is open, the app keeps a rolling 10–15 seconds of audio, so tapping saves the babble that has *just* happened. The cost is that the microphone is on whenever the screen is open (Android shows its privacy dot), plus some battery. It would be off by default, with a setting to turn it on.
4. **Names:** is `qdvc-dahdoo-android` right for the repo, with `qdvc.dahdoo.android.app` as the package?

### Other features worth considering
